## 1. 현재 UX 분석 (개선 전)

| 화면 | 관찰 | 사용자가 망설이는 이유 |
|---|---|---|
| 첫 화면 | 시작 버튼이 등장 효과로 **약 1.6초 뒤** 나타남 (`.btn--primary`에 0.8s 지연 + 0.8s 효과). 0.3초 캡처 시 제목 반쪽만 보임 (`01-mobile-home-first-moment.png`) | 처음 1–2초 동안 "무엇을 누르는지"가 없음 |
| 첫 화면 | 메인 카피가 질문 한 줄 + 3줄 설명. 버튼 문구 "5분 역사 인식 **조사** 참여하기" | 탐구가 아니라 설문처럼 보임. 참여하면 무엇을 얻는지(카드) 보이지 않음 |
| 첫 화면 | "참여 방법" 4단계(연령대→역사→생각→결과)가 실제 사건 화면의 5단계 진행 표시와 이름·개수가 다름 | 단계 감각이 화면마다 바뀜 |
| QR 진입 | 맨 위에 5단계 진행 표시(번호만), "다음 …바로 가기" 안내, 새 참여자 링크 → 사건 제목 → 설명 → **그 아래**에 탐구 전 입력 | 첫 화면에 입력창이 없음. 무엇이 핵심 질문인지 경쟁 |
| QR 진입 | 탐구 전 카드 안에 "저장하고 시작"·"건너뛰기" + 학습 경험 4버튼 | 버튼이 여러 개라 주요 행동이 하나로 안 보임 |
| 탭 | 탭 6개(서술·어떻게 다를까·단어 빈도·사료·내 한 문장·모두의 기억)가 같은 무게. 모바일에서 4번째 탭부터 화면 밖 | **"내 한 문장 쓰기" 탭이 모바일 첫 화면에서 보이지 않음** |
| 서술 비교 | 서술 카드 3개마다 키워드·편집자 해설·출처가 모두 펼쳐져 모바일 페이지 높이 약 4,000px. 다음 행동 버튼은 맨 아래 | 끝까지 스크롤해야 다음 단계를 찾음 |
| NLP 분석 | "한눈에 비교"는 좋은 요약이지만 별도 탭 안에 있어 서술과 떨어져 있음 | 서술을 읽는 화면에서는 공통점·차이점이 안 보임 |
| 공동 표현 | 닉네임 → 연령대 → 개인정보 안내 → STEP 1~4(요소·방식·문장·이유) → 카드 만들기 → 공개 | 핵심 입력(문장)이 다섯 번째 블록. "STEP 1~4"가 전체 진행 단계와 혼동 |
| 미완료 | 카드 만들기 실패 안내가 버튼 아래 작은 글씨 | 버튼을 눌러도 반응이 없는 것처럼 느낄 수 있음 |
| 저장 구조 | 탐구 전 문장·학습 경험·진행 기록은 `localStorage(sm_*)`, 카드 내용은 창 메모리, 공개 시에만 Supabase | (구조는 적절 — 이번 작업에서 그대로 유지) |

## 2. 변경 계획 → 구현

### 4단계 탐구 경험 (사건 화면 = STEP 1~3, 카드 화면 = STEP 4)

| 단계 | 화면 핵심 질문 | 하단 고정 주요 버튼 (단계마다 하나) |
|---|---|---|
| STEP 1/4 내가 아는 역사 | 이 사건에 대해 **지금 알고 있는 것**을 한 문장으로 | `내 생각 저장하고 세 나라 기록 보기 →` |
| STEP 2/4 세 나라 비교 | 세 나라는 같은 사건을 **어떻게 다르게** 기록했을까요? | `발견한 관점으로 내 표현 쓰기 →` |
| STEP 3/4 나의 표현 | 탐구를 마친 지금, 이 역사를 **어떻게 기억하고** 싶나요? | `My Memory Card 만들기 →` |
| STEP 4/4 Memory Card | 나의 Memory Card가 완성되었어요 | `이미지로 저장 ↓` (모바일 하단 고정) |

- **진행 표시**: `STEP n/4 + 단계 이름 + 진행 막대 + 완료 ✓`. 각 단계 번호를 눌러 언제든 이동(잠금 없음). 하단 버튼 위에도 `STEP n/4 · 이름`이 항상 보임.
- **이전 단계**: 하단 `← 이전` 버튼, 카드 화면의 "STEP 3 · 내 표현 고치기"와 진행 표시 버튼.
- **미완료 안내**: 막지 않고 버튼 바로 위에 이유를 표시 (STEP 1 빈 칸: "아직 한 문장을 적지 않았어요… 한 번 더 누르세요" + 버튼 문구가 "적지 않고 …"로 바뀜 / STEP 3 빈 칸: "‘② 나의 최종 표현’ 칸에 …" + 입력창으로 이동·초점).
- **복잡한 기능은 삭제하지 않고 뒤로**: NLP 계산 과정·단어 빈도·사료는 STEP 2의 "더 깊이 살펴보기"와 탭에, 편집자 해설·키워드·타임라인은 접힌 "자세히 보기"에, 핵심 요소·표현 방식·이유는 STEP 3의 "표현을 다듬는 도구 더 보기"에, 닉네임·연령대는 "공개하기" 영역으로 옮김(공개할 때만 쓰이는 정보이므로).
- **STEP 3에 '새롭게 발견한 관점'**: 카드 화면에만 있던 선택지를 STEP 3에서 먼저 고르게 함(같은 상태를 공유, 카드 화면에서도 수정 가능).

### 시각 강조 (분석된 것만)
- **형광펜**은 `computeGlance(eventNlp)`의 실제 계산 결과(세 서술 공통 표현·서술별 특징적 표현)에만, NLP 모듈이 찾은 원문 위치(첫 등장)에만 칠합니다. 서술마다 최대 4개. 범례에 "자동 계산(NLP) · 중요도나 옳고 그름이 아님"을 명시. 편집자 해설은 강조하지 않습니다. (E2E에서 모든 `<mark>`가 계산 결과 단어인지 검사)
- 두드러진 표현은 색 + **굵기**로 구분(색각 차이 대비).
- **공통점·차이점 카드**: ① 같은 사건, 서로 다른 이름(사건 데이터) ② 공통점(NLP) ③④⑤ 한국·일본·중국 측 차이점(NLP). 단어를 누르면 기존 근거·사료 화면으로 이동.
- 제목용 형광펜(`.hl-ink`)은 디자인 강조이며 분석 결과로 표시하지 않습니다.

### 첫 화면(Hero) 재설계
- 메인 카피 **"같은 역사, 다른 기억."**(최대 5.4rem, '다른 기억'에 절제된 형광펜) + 서브 "당신은 어떻게 기억하나요?" + 한 줄 설명.
- 큰 알약형 CTA **"5분 탐구 시작하기 →"** 하나(모바일 전체 폭, 60px 높이). 등장 지연 1.6초 → 0.35초.
- **Memory Card 미리보기**: 기울인 종이 2장 레이어 + 부드러운 그림자, "예시" 배지와 "(예시 문장)" 캡션으로 실제 참여 결과가 아님을 표시.
- 아래에 사건 화면과 같은 이름의 4단계 띠. 기존 소개 카드·QR·About 링크는 그대로.
- 한지 베이지·먹색·accent·국가색 유지, 새 색은 형광펜 2색뿐. `prefers-reduced-motion` 존중.

### 모바일
- 하단 고정 CTA(안전 영역 포함). 키보드가 열리면: Android는 `interactive-widget=resizes-content`, iOS는 `visualViewport`로 버튼을 키보드 위로 올림. 버튼 영역 실제 높이를 `scroll-padding-bottom`에 반영해 입력창을 가리지 않음.
- 가로 넘침 수정(새 첫 화면 장식), 터치 높이 40–60px, 키보드 초점 표시(`:focus-visible`), 진행 표시 `aria-current="step"`, 형광펜에 스크린리더용 설명.

## 3. 클릭 수와 동선

| 경로 | 개선 전 | 개선 후 |
|---|---|---|
| QR → 탐구 시작(입력) | 0클릭, 단 입력창이 첫 화면 밖 | 0클릭, **입력창·질문·버튼이 첫 화면 안** |
| QR → 카드 저장 | 저장 1 → (약 4,000px 스크롤 또는 화면 밖 탭 찾기) → 탭 1 → (닉네임·연령대·STEP 1~4 지나서) 카드 1 → 저장 1 = 4클릭 + 탐색 | 하단 버튼만 4번: 저장 → 내 표현 쓰기 → 카드 만들기 → 이미지 저장 (**같은 위치, 탐색 없음**) |
| 홈 → 탐구 시작 | 시작 → 연령대 → 다음 → 사건 = 4클릭 | 동일 4클릭 (연령대 익명 통계 유지를 위해 단계 수는 줄이지 않음) |

> 홈 경로의 연령대 단계는 기존 연구·통계 데이터(age_group) 수집과 연결되어 있어 유지했습니다. 줄이려면(예: 연령대를 공개 단계로 옮기기) 데이터 수집 방식 변경이므로 별도 결정이 필요합니다.

## 5. 실제 사용자 테스트가 필요한 부분 (자동 테스트로 검증되지 않음)

자동 테스트는 "버튼이 보이고 동작한다"까지만 확인합니다. **직관성 자체는 검증되지 않았습니다.**

1. **3초 인식**: 처음 보는 학생 5–8명에게 첫 화면/QR 화면을 3초 보여주고 "무엇을 하는 곳인지, 어디를 누를지" 물어보기.
2. **실제 기기 키보드**: iPhone Safari·Android Chrome에서 STEP 1·3 입력 시 하단 버튼이 키보드 위에 오는지, 가리는 곳이 없는지 (헤드리스 브라우저는 가상 키보드를 재현하지 못함).
3. **완주율·소요 시간**: QR → 카드 저장까지 걸린 시간과 중도 이탈 단계 (5분은 목표치).
4. **형광펜 이해도**: 학생이 형광펜을 "정답/중요"로 오해하지 않는지, 범례를 읽는지.
5. **STEP 1 건너뛰기 비율**: 두 번 누르면 넘어가는 안내가 압박으로 느껴지는지.
6. **스크린리더 실기기**(VoiceOver/TalkBack)로 진행 표시·하단 버튼 순서 확인.
7. 작은 화면(320px)·큰 글자 설정·가로 모드.
